# 真實項目導入前的下一階段建議

2026-11-02。使用者已同意先補強前三項。以下保留原有導入安排，實作與驗證見末節；不把工具功能完成等同真實項目驗收通過。

## 先用一個真實項目貫穿，再補通用能力

主線保持：人在面板描述目的、標記與核對答案；Pi 編寫或重用算法；平台負責可執行性、來源、數據契約及結果統計。暫不逐個封裝 OpenCV 算子為 tools，也不提前堆大型模組庫。

| 優先 | 導入前準備 | 驗收方式 |
|---|---|---|
| 1 | 建立一份項目驗收約定：輸入來源／工件單位、互斥且完備的類別、判定規則、缺測歸類、故障處理、時間預算 | Pi 整理，缺失時在待諮詢提出具體問題；人類確認來源。不得從檔名生成 ground truth，也不能以通過 schema 代替算法有效 |
| 2 | 整理真實圖片的開發集與保留驗收集，涵蓋邊界、反例、失焦／遮擋等現場條件；按實際批次或工件分組，避免近重複圖片跨集合洩漏 | 固定人工答案及其來源、數據身份與方案版本。分開報告有答案覆蓋、漏檢／誤判、每類召回和故障，不用幾張反覆跑的數量冒稱樣本量 |
| 3 | 驗收一遍失敗案例閉環：統計異常 → 原圖／關鍵結果／標註 → Pi 解釋及修改 → 重跑基準集 → 對比變化 | 沿現有快照、歷史產物、時間線與方案版本接通交互，保留固定工件與參數。修好一張後不能破壞已通過樣本；有分歧時記錄，不自改人類答案 |
| 4 | 確認全週期性能口徑，在目標硬體上測冷啟動、穩態、長時間連續運行 | 覆蓋輸入取得、解碼／前處理、算法、分類、必須的輸出與保存；顯示 P50/P95/P99、最大值、超時比例與記憶體趨勢，不能只報算子時間。節拍與非同步保存分開，不能用隱藏成本達標 |

已有的討論快照、方案版本、分類與統計應優先整合使用。先用一個項目找出實際阻礙，再針對阻礙加功能。若準備工作拖住真實項目，就先做 1、2 並立即導入，3、4 隨實測補強。
