從成像資料，到可驗證的通用工件檢測

本版實作已討論的七步，工件、部件及檢查項由使用者定義，不預設特定部件或外框目標。本機桌面程式：13-cv/AgentCV.app。更新後請退出舊窗口，再開啟此程式。

七步工作台

步驟實際可做的工作
1 圖片與成像配置單張／多張／文件夾導入、改名、逐圖配置；像元、倍率、工作距離、Binning、裁切起點與重採樣比例；雙軸實測比例或在圖上畫已知長度標定。理論與有效實測分開。
2 工件參考資料導入原件、文字讀取、圖片預覽、來源關聯；文字摘錄進 Agent 上下文。未解析格式明確標示，可開原件；可略過及後補。
3 識別並確認工件從本圖像素重算前景候選，明示來源／閾值／取樣間隔；採用、人工修正與原圖指紋均保存。舊版無紀錄時標為來源未知。人工採用或矩形／鋼筆圈選；可移動、拖頂點、右鍵刪除／註解、撤銷與重做。候選不是精密分割結果。
4 部件與關係自訂通用部件、逐圖範圍、說明、包含／裝配／基準／相鄰關係；模型可被多個檢查項引用。
5 品質示教建立寬度、高度、兩區域中心距、邊緣傾角或存在性檢查；公差與依據可逐步補充；逐圖逐項人工 OK／NG／UNKNOWN 與原因，保留原整圖標籤。
6 建立方案畫布下方常駐參考模板→定位→找線→量測→判定五步，點選同步切換畫布證據；存在性只顯示三步。方案來自已確認示教與內建算法編譯，並非模型自主搜尋算法。展開查看輸入／算法／輸出、實際門檻、適用限制與圖片集證據；高級匹配／找線參數；查看合格多候選、搜尋 ROI 與拒絕原因，可從對話框或直接點畫布選線並記錄到新配方。
7 驗證與發布逐圖重算、按人工答案顯示正確／漏檢／誤拒／UNKNOWN，匯出 CSV；每項檢查需獨立且不同於模板的有標註圖片通過，且沒有當前人工確認錯位，才可發布唯讀快照。依賴或標籤變更使驗證／發布失效。

0.9.8：取消第一組通過就停止，補齊參數比較

四邊各完整計算 1／5／9／15 px × 中段 60%／50% 八組。新增原圖各組線位疊合、逐組 RMS／覆蓋／連續性／線位差表、參數敏感度曲線。矩陣用不同顏色區分「可用」和「採用」，不再把未試設定當成較差。

先按品質與意圖條件篩選，再比較共同支持跨度的線位。有歧義、沒有共同跨度或跨組線位差超過 3 px 時保留 UNKNOWN；3 px 沿用本版候選歧義的工程尺度，未按尺寸誤差預算校準。其餘優先較窄平均，同寬優先較長搜尋段，以減少額外平滑；不宣稱最低 RMS 或全域最優。只有一組通過仍可作目前幾何量測，但明示「缺少參數一致性證據」，不稱穩健。跨圖驗證仍在第七步獨立進行。

project1 上邊八組合格線的最大線位極差為 0.1434 px；1 px 的 RMS 為 0.4053 px，15 px 為 0.3178 px，兩者取捨直接可見。左邊仍只有 15 px／50% 通過。四邊採用值與原保存寬度相同，原件未修改。新增比較會改變部分其他圖的採用結果或輸出 UNKNOWN，因此算法版本升至 0.9.8，舊驗證須重建重跑。

可操作模塊與數值來源

前景工具檢視器加入「參數／輸出／依據」模塊。圖下的閾值與採樣間隔可直接改；修改會切為手動，經短暫防抖後由實際Worker重算下游圖像。舊圖在等待時淡化，未算完或有錯誤不能採用。輸出格數與滑鼠讀值保持唯讀；固定工程約束明確標示。

數值來源及可調方式
Otsu 閾值由本圖採樣灰階直方圖掃描組間變異，取最早最大值。不是固定64。可直接改數字或點曲線設為手動，亦可恢復自動；曲線同時保留自動峰值與實際使用值。
採樣間隔自動 max(1,ceil(max(寬,高)/400))，400是本版速度策略。可改1–64px，最多400萬格；細節與計算量需核對。
白色條件與格數條件由候選極性與有效閾值推導；格數是遮罩的實算輸出，不可直接改格數。滑鼠讀值顯示其原圖／採樣座標。

修改預設只作本圖範圍示教預覽。按「採用此候選範圍」後才保存ROI、實際參數及來源，並使依賴方案與驗證失效；關閉或切換圖片不會偷偷採用。重開專案後使用已採用的本圖設定重建。第六步跨圖檢測仍依其模板定位、找線與量測方案執行，不能把本圖分割預覽當作所有圖片已檢測。

原圖自動64／手動128的曲線與遮罩實算對照，數據紀錄。

工具說明與引用提問

前景五步與方案五步的工具名旁有「?」。說明分為原理及輸入輸出、參數來源、適用邊界，以分頁避免長面板滾動。可以引用整段，亦可選取部分文字引用到對話。引用附帶工具名稱、原文、圖片指紋、當時輸入與實算輸出快照；待計算與未採用狀態會分開標明。前景引用保留直方圖，但不傳整張遮罩陣列。

引用只生成可編輯草稿，按傳送才呼叫Pi。已送出的對話保留原引用快照，不會被下一個草稿覆蓋；換圖前未送出的引用不會混到新圖。引用及快照保存到專案對話；引用文字被當作資料，不當系統指令。OpenCV 官方閾值原理參考，實際計算為AgentCV本機實作。

圖像優先的範圍生成過程

第三步按「查看生成過程」：原圖 → 灰階／取樣 → 閾值分割 → 連通區 → 凸包。上方是實際中間圖縮圖，下方預設前後對照；可同步縮放／平移、1:1像素檢視、疊回原圖及切換候選。綠色為選定連通區，橙色標出凸包新增的凹陷或孔洞範圍。數據放在圖下，來源文字收在「來源詳情」。

灰階、二值遮罩和連通區標籤來自同一次實際Worker運算，不是示意圖片；只切換檢視不改參數；參數試調在採用前不改已確認圈選。計算使用最近鄰灰階採樣，顯示不作平滑插值。原圖的像素間隔與計算網格分開標示，不能把採樣格誤認為原圖逐像素分割。

灰階／遮罩／標籤的大型陣列暫存於記憶體，不傳給 Pi，也不塞入專案JSON；引用提問會保存小型直方圖及數據快照。重開專案後可由原圖重新分析，但明示這是重新運算重建；人工圈選、Agent提議及來源未知的舊輪廓不會被冒稱為Otsu結果。平坦圖像若無閾值可用，流程停在灰階，不捏造後續圖像。

Pi 對話與帳戶

  • Pi SDK 執行 Agent；界面明示服務商、模型與連線狀態，從已配置服務商切換模型。
  • /help、/login、/logout、/model、/new、/stop由宿主處理，不當成普通聊天發給模型。
  • 專用 OAuth／API Key 流程、取消、登出與模型刷新；憑證不進專案或對話。
  • 額度耗盡、認證失效、網路錯誤分開呈現。重新登入不被當成額度問題的解法。
  • 模型可讀目前階段、成像狀態、工件／部件／關係、可讀資料和真實結果；可提出範圍、檢查項及人工答案映射供人核對。模型不能自行產生驗收真值或發布。
  • 附上目前圖片須明確勾選；未傳圖片不能宣稱看到了原圖，未解析資料不能宣稱理解。手動修改／拖曳後，過期工具請求不能覆蓋新狀態。

保存與舊專案

「保存」使用專案文件夾：manifest.agentcv.json 與 assets/。原圖／附件用 SHA-256 內容位址去重，載入校驗雜湊與大小；清單原子替換，拒絕路徑穿越和資產符號連結，適合 Git 管理。可另匯出便攜 JSON，亦可導入舊 JSON；原件不會被自動覆寫。重開後已計算結果需要重新驗證。未保存關窗有保存／放棄／繼續工作的明確選擇。

算法能力與限制

目前是固定工位、同解析度、平移定位、近矩形目標的幾何量測與規則分類。前景候選使用閾值與連通區包絡；定位使用灰階模板相關性、絕對誤差及唯一性門檻；找線使用覆蓋、連續性、局部支持、殘差與角度檢查，切向平均由 1／5／9／15 自適應嘗試。量測使用真實擬合邊線及交點，手畫輪廓僅表達搜尋意圖。

  • 定位只支持同解析度平移，未建立旋轉、尺度、遮擋的獨立檢出器，這些變化可能仍通過現有門檻。22 × 22 稀疏灰階取樣不是逐像素外觀全檢：合成圖避開取樣點遮黑 1,500 像素，仍可得到 ZNCC≈1、MAE=0 及有效矩形量測；不能據此證明無缺陷。
