# AgentCV 工程本體：概念、關係與已證實的失敗規則

此文件是平台本身的工程語義，不是 HALCON runtime，也不宣稱整合了外部知識庫。可機讀關係見同目錄 engineering-model.json。新問題先核對這些關係；方法可自由選擇，工程對象與證據不可混淆。

| 對象 | 真正關係 | 不應混同 |
| --- | --- | --- |
| 圖像源 DatasetSource | contains 原圖身份，feeds 單件執行 | 圖片數不是單次輸入數 |
| 工件 WorkpieceUnit | hasView 待檢影像；appliesScheme 固定方案 | 多相機同件才是多視圖 |
| 固定參考 ReferenceAsset | referenceFor 待檢對象；boundBy slot＋內容hash | 不是待檢工件，不進逐件計數 |
| 工程節點 PurposeNode | contains 算子及子目的，requires 實際接口產物 | 不能把一次trace當完整宣告圖 |
| 算子 Invocation | produces 產物；requires/any_of/when 確定依賴 | 正常未找到不是執行故障 |
| 分類 ClassificationSpec | partitions 正常結果；mapsMissing 無量測 | 多缺陷標籤不等於多個最終類 |
| 系統出口 ExecutionExit | PRODUCT:category／FAULT／CANCELLED | FAULT不是正確NG命中 |
| 結構圖層 CalculatedLayer | producedBy run/step，locatedIn 原圖座標 | 螢幕排版位置不是原圖坐標 |
| 顯示引用 DisplayReference | displays 真圖層並明示transform | 不增加計算依賴 |
| 解說 EvidenceRevision | explains 原執行，appendOnly 後續修訂 | 不能改寫原程式／原實測事實 |
| 回歸 Regression | compares 真值及實測，keeps provenance | Agent推斷不是獨立人工真值 |

工程目的嵌套至多三層。父目的狀態包含子目的可用性；父節點自身程式成功不代表子目的也成功。明確替代分支可以恢復正常NOT_FOUND，不能把真正FAULT洗成普通產品NG。

## 依據與驗收

每個已執行算子需要真計時及節點文檔；沒有trace的裸腳本只可診斷，不標成逐算子已驗證。節點文檔是方法、參數選擇和邊界，不是三份相同輸出圖。對比用相同原圖與共同量；未比較的預算或門檻明說是試驗設定。結構完整、真輸出、獨立回歸、召回與現場採用是不同關係，不能以一個PASS替代其他條件。

## 從本次真失敗得到的工作規則

- **SDK可發現性**：先讀capabilities及structured-layers.md，尤其geometry與coordinateSpace。不要用整方案替換來探測SDK；source使用當前context原樣回傳。
- **圖層可消費性**：有PNG或JSON檔不表示畫板能選取幾何。保存後用get_canvas_layers讀回有效物件及diagnostics；舊壞層不可阻塞新層。參數位置錯誤按path/hint修正後真重算，不改歷史facts。
- **分類守恆**：每件一個final categoryId，多瑕疵另列defectLabels。分類合計等於正常分類件數，包含FAULT/CANCELLED的出口合計等於processed。重疊與空隙是需釐清的規格，不能用不透明的中間類掩蓋。
- **圖有用途**：每張原圖要能指出圖像源與角色。模板到場景的映射應展示兩源點對、投影結果、參數比較及失敗原因；不能用無關圖片寬度分檔冒充良品判定。
- **持久紀錄**：讀回原存檔不得丟失更新的依據修訂；切換專案或選件時，舊的異步回覆不得寫入新位置。整批含故障或取消的歷史不能只取最後成功件當作總狀態。
- **畫板與模型負載**：大量圖在圖像源分頁，單件結果按需讀；不把整圖集展開。問詢超出16張先明示選圖，保留草稿。單畫板32顯示引用滿載時，使用者可點選，Agent 可用 create_linked_canvas_board 建立關聯空畫板（默認不切換視圖），再明確指定 board_id 發布；原圖、歷史問答與實算仍保留。這是現有資源限制，不是無限畫布的承諾。

本次失敗及修復來源在本機 codex-audit-logs/20261029-core-redesign、20261029-core-pi-live-final、20261029-core-pi-followup-selected；可機讀本體保留對應證據路徑。失敗的Pi回合保留INCOMPLETE，更新skill不會回頭把它們改成成功。

- **持久圖片的可驗證性**：圖像沒有內嵌dataURL不等於缺圖。使用宿主核對過的檔案／CAS引用及一致SHA、大小、MIME和尺寸；未驗證引用仍不可當圖像證據。不要為修顯示而放鬆步驟ownership或改寫歷史審計。
- **預設回歸角色**：固定參考圖即使在工程圖片索引中，也必須從預設待檢迭代與total排除；切換單件時圖像源選中圖要與實際active圖同步。

## 分類決策與分支的建構契約

一次分類決策對應一個菱形節點。classificationSpec.rules、missing 與 fallback 是該決策的分支條件，不是額外工程節點；同一類別的條件歸入同一出口分支，條件標在連線並可展開。規則優先序與最終類別彙總仍需明確保存，不把「條件命中」當成「最終到達」；只依保存的唯一 finalExit 高亮出口。只有需要新輸入、產生中間結果或控制不同後續運算的獨立決策，才另建節點；不可把真正有先後依賴的決策合併。圖形由宿主共用分類契約生成，不以新增Python節點重複classificationSpec已負責的最終分類。

- ClassificationSpec → 一個 ClassificationDecision；其 ClassificationBranch 直達 CategoryExit。
- 分支保留原規則 ID、條件樹、缺量測映射、fallback 以及衝突／類別優先序。候選條件不能單獨宣稱就是最終出口的完整互斥判詞；最終出口由固定分類執行器選出。
- 保存的摘要若只有最終類別，能標示到達出口，但不能補造命中哪條規則。FAULT 獨立離開，不走產品分類。
- 共用建構檢查拒絕同一規格多個分類決策、條件節點、重複出口、漏條件或多出口高亮；原程式、既有執行紀錄不因此重寫。


## 顯示與執行狀態契約

- **當前工件與歷史不可混用**：流程圖狀態和即時輸出必須選中相同方案指紋、同一當前工件的最新執行。切到固定參考圖或未執行圖片時，顯示尚未執行／等待，不借用末筆工件或上次打開歷史紀錄的分類。固定參考是檢測依據，不會因被點選就獲得待檢工件的 OK／NG。只有明確查看歷史 runId 時才能顯示其他工件紀錄，並標出歷史身份；真正執行中則以正在處理的單件身份為準。

- **節點顏色來自真實執行**：等待保持底色，運行中黃色，成功綠色（包含正常 NOT_FOUND 與成功分類為 NG），只有執行故障紅色，未走或前提失敗而跳過為灰色；FAULT 以故障標記區分。分類模塊成功算出 NG 仍屬成功執行，產品類別另標；不能從紅綠背景推定產品良率。新工件開始時不沿用上件綠色。
- **即時輸出模式**：只顯示當前工件、目前可執行方案與該節點明確宣告的輸出接口。多張輸出可並列切換；缺測、未跑、過期或讀取失敗明示，不能回退到上一張成功圖。程序尚未產生的分支不可偽裝成輸出。
- **協作畫布模式**：可保留固定原圖、過程圖、比較圖及歷史討論，也可新增獨立的即時圖卡。圖卡的 live 訂閱綁定 schemeId／schemeNodeId／artifactId；固定圖不隨執行更新，不能將畫布所有圖都稱為即時資訊。
- **共享操作與來源**：get_canvas_image_mode 讀取幀狀態；set_canvas_image_mode 設定 Agent 自己獨立圖卡的 live／fixed。已有標註、量測、工程師物件或固定實算圖組不可直接改成即時訂閱；以 add_visual_image 新增自己的獨立圖卡後訂閱。不能繞過宿主檢查改寫歷史。
- **提問固定當時依據**：從輸出切到畫布圈選提問、或引用即時圖卡時，保存當時像素、工件、runId、artifactId 與 SHA 的快照。後續執行與模式切換不改寫已送出的問題。標註即時圖前先固定已就緒幀；尚未就緒不可用舊圖頂替。
- **改名不等於重算**：rename_flow_node 改顯示名稱，名稱存於 presentation.nodeTitles；穩定 ID、可執行程式及已保存實算身份保持原樣。參數、來源、連線或分類改變則必須重新核對受影響結果。


## 諮詢回答必須落到規格

人類在諮詢卡回答後，先用 get_canvas_consultations 讀取原問題、最新回答時間、來源、當前規格及採用狀態。ANSWERED_PENDING 表示尚待解讀；SPEC_UPDATED_UNLINKED 表示相關問題已不再由檢查器提出，但還沒有這份回答的採用回執。兩者都不能僅回覆「已保存」就結束。

根據回答解讀所屬完整欄位（execution.timingRequirement 或 classificationSpec），保留無關設定，使用 apply_canvas_consultation 提交 patch、回答時間、當前方案指紋與解讀理由。不要以硬編碼關鍵字猜標準，或把「300ms」變成所有專案的預設。回答語義仍有歧義、或與其他圖像源共用規格衝突時，在同一諮詢對話明確詢問，不把已回答直接改為已解決。

提交後讀回 get_canvas_consultations：APPLIED 只表示精確回答已有回執、當前欄位與回執相同且通過結構檢查；告訴工程師實際寫入的值與來源。RECHECK_REQUIRED 表示規格或答案又變更，需要重新核對。全方案仍有缺漏則繼續處理；不要把欄位檢查通過說成精度、召回率、耗時或現場驗收達標。修改規格後舊執行仍需依新方案驗證。


## 諮詢 patch 的精確格式

apply_canvas_consultation 的 patch_json 使用一個字面點分鍵：`{"execution.timingRequirement":{"maxUnitMs":…}}`，不是巢狀 execution 物件；classificationSpec 則以 `{"classificationSpec":完整分類規格}` 提交。宿主自動綁定原始回答 provenance。值來自當前回答，不能拿格式示例作工程預設。若卡綁到固定參考圖，先核對真正待檢來源再用 rebind_canvas_card 修正，原回答來源必須保留。

### 人工答案、節點耗時與單件週期

圖片圖集中的人工分類是回歸答案來源，執行器應讀取 image.expected；不能只讀另外傳入的 units.expected 而丟棄圖片標記。舊 OK/NG 僅在品質唯一對應一個類別時可解析，多分檔要請人類選明確類別；不能由檔名或算法輸出反推答案。修改答案後舊實算仍是歷史，不自動改寫其混淆統計。

節點／算子顯示保存的實測 durationMs；巢狀計時不可相加當牆鐘時間。單件判定時間截至分類完成，主機週期可另含結果保存（查看 cycleIncludesDurableSave）；兩者均不含尚未量測的相機觸發或PLC延遲。時間檢查用逐件上限與缺測數，不以平均低於門檻宣稱通過。分類結果NG不等於程式失敗；節點背景只表示執行狀態，品質用獨立標記。


### 分類結果的判定依據圖

圖像源左右對照原圖與同一工件、同一次執行的判定依據。OK 預設讀最後已執行節點宣告 role=result 的圖；NG 沿命中分類規則的 metricBindings 找實際產生該量的節點，而非永遠拿最後節點。

可在 classificationSpec.categories[].evidence（OK總覽／保底分類）、rules[].evidence（命中原因）、metrics[].evidence（量測缺失）聲明 `[{nodeId,artifactId,label?}]`。引用必須對應方案節點 expected_outputs 中 type=image 的真實產物；label 是圖的說明，不是分類答案。需要凸顯超差、失敗搜索範圍或瑕疵時，在該節點產生合適的實算圖層／圖像並綁定，不能用通用輸出冒充原因證據。編譯器會拒絕無效引用。

宿主保存所有實際命中的規則 matchedRuleIds，ruleIds 保留優先級決議；展示先按最終類別，再按已宣告的規則優先序，其他原因仍可切換。未執行節點需標明；FAULT只可顯示標為「故障前影像」的最後有效圖，不作產品NG。缺少圖就明說，不能借用別件／別次產物。舊結果按歷史方案解讀，修改方案後重新執行才有新依據。正常檢測選圖由平台完成，不逐件呼叫Agent。


### 千張連續執行與時間對帳

流程圖的「程式 ms」是 Python 計時，含該程序內導入、解碼及產物寫入；不等於單件主機牆鐘週期。新單件紀錄 timing.breakdown 保存互斥分段（原圖準備、節點準備、派發、結果檢查、同步監聽、分類、其餘編排），總和要等於 timing.totalMs。nodes[].native 是派發內層，不可重複相加。差額項不得直接叫作純Python啟動；viewTiming 可與原生執行重疊，也不能加回總耗時。舊紀錄未量測的部分不得補估成實測。

長序列逐件運行、逐件保存；UI進度合併不等於丟棄運算結果。每150ms至多更新一次執行畫面，完成後刷新完整畫板；原圖使用有界快取，歷史產物按需讀取，不把千張圖鋪在畫板或載入像素。吞吐測試可重複真實影像，但必須揭露獨立原圖數量、測試的實際執行器與UI範圍，不能宣稱為千個獨立準確率樣本或產線節拍驗收。

- 千件連續執行的顯示層也須有界：主介面與畫板訂閱同一狀態時不得各自重建；統一節流並保留最後狀態。即時圖更新後，移除已無資產引用的解碼預覽；人工固定或提問引用的資產仍保留。壓力測試必須說明是否包含原生畫面、圖像尺寸、獨立樣本數，重複圖測吞吐不得宣稱獨立準確率驗收。


### 產線時限與執行後端（設計／驗收要求，非現有能力宣告）

當需求含單件50ms或更短時，先約定計時起終點：圖像到齊至分類、觸發至輸出／致動、完整存檔完成分開量測。不能以Python算子和、平均值、無視窗核心微基準代替整條鏈；報P95/P99/最大、逾時數、排隊延遲和冷啟動，沒有硬件數據時不得宣稱現場達標。

檢查逐節點啟動進程、重複原圖編解碼、固定模板特徵重算、參數掃描、解釋圖壓縮與存檔是否進入決策關鍵路徑。參數對照應保留在方案開發／驗收歷史；正常檢測執行已採用配置。確屬算法必要的自適應比較不得擅自刪除，需保留依據及整體回歸。

本專案優先考慮Rust常駐執行核心與原生算法後端，Python仍可用於開發或擴展，不能因性能優化封死任意算法能力；某後端未達時限則明確標示，不冒充已部署。UI、編譯與不同後端必須共用同一方案／節點／分支語義並追溯版本，禁止另外手工寫一條不受方案控制的生產流程。固定模板快取需以內容、參數、算子版本、標定等依賴失效。

逐件決策保存必要數值、幾何、來源與版本；顯示／診斷PNG可異步生成，但作為下游輸入的圖像必須正常傳遞。異步存檔與顯示隊列有界，必存紀錄滿載必須明確背壓／受控停機／故障，不可靜默丟失。異步保存完成另行計時；若驗收要求存檔後才允許放行，就必須算進週期。


### 專案控制與懸浮面板

AgentCV 的項目級操作（執行、統計、分類規格、諮詢、版本）由左側專案控制區提供。畫板保留圖像源、參考資料、局部標註、關係與就地對話；統計等使用非模態懸浮面板，面板仍須保留圖像來源、方案版本與真實執行的可追溯性。將卡片移出畫布是呈現改動，不能刪除來源關係、規格、回答或歷史。畫板圖組／標籤仍引用的生產者運算，必須納入回收保護；缺失時按原始存檔與雜湊核對恢復，不虛構圖組輸入。


### 本步工作區與固定圖文討論

預設集中顯示目前節點的實際輸入與主要輸出，過程圖收進本步圖集；只按方案宣告的真實輸出發布主結果，不把所有診斷圖自動鋪到畫布。輸入圖需核對 producer、artifact 與同一工件／執行綁定；原圖需核對內容雜湊。找不到來源時說明缺失，不拿其他工件圖補位。

即時圖在開始標記或引用討論時固定。討論保存當時像素、標記幾何、來源run／artifact／工件、方案指紋及各輪問答；切換圖片或重算不得替換該依據。送模型的是標註渲染圖與結構化來源／幾何，固定討論圖不可冒充目前即時輸出。回到目前狀態時重新讀取／執行，歷史討論繼續保留。

使用者可在問題中以 @ 搜尋原圖、已載入紀錄的節點圖與帶標記的討論圖，加入本輪固定引用後再標註。來源必須可辨別目前／其他工件、步驟及歷史；完整封存紀錄可先從歷史預覽按需載回。跨步驟引用不會產生算法依賴邊，也不自動更改現行方案；需要改依賴時，另行修改同一份可編譯方案。

圖文時間線保留討論，方案指紋分組保留該方案的實算紀錄；二者不能互相冒充。回合前後指紋不同只表示期間發生方案改動，不代表已驗證改動由該問題引起。歷史預覽為只讀，不因預覽而切換目前工件或採用舊方案。


### 專案實算統計

統計為專案級懸浮面板，不提供圖像源選擇或上傳入口。使用總覽、時間、品質、異常分頁；大量結果用聚合圖、篩選與頁內分頁，不堆成長頁。時間採目前方案的真實執行次數，品質採同方案每個工件最新判定及執行時保存的人工答案。標註後需重新執行才能產生新回歸證據，不能改寫歷史答案。

方案指紋不同的紀錄不可混入。重複執行不代表新增獨立樣本，需區別次數、圖片與不同圖片內容；分母缺失顯示無資料，不以零或百分之百補位。故障、取消與未分類獨立於產品類別，總數需對得上。判定耗時與主機週期分列，明示上限、超時、保存範圍及未含的設備延遲；大量趨勢聚合須保留尖峰。上述統計由平台讀取真實紀錄保障，Agent 不生成統計數值。

## 交互響應與必要紀錄

快速響應是平台基本要求。驗收圖片切換與檢測，必須分開量測點選到原圖、點選到本件依據圖、算子耗時及可再次操作的時間；不能只用算子耗時或靜態預覽測試宣稱卡頓已修復。檢測一次只處理選中的工件，縮圖、被遮住的畫板重建、全專案 JSON 複製與版本封存不得阻塞前景顯示。

正常逐件檢測保存本件分類、量測、時間、來源身份與證據引用，並保存當次方案定義供追溯；不要每點一張圖就再建立包含全部歷史圖像的專案 Git 快照。方案開發與修改仍由版本管理保存。已成功持久化、且沒有人類引用的舊執行產物可退出活動記憶體，歷史按需讀取；不能移除未持久化或人類標記、對話引用所需內容。使用者刪除的歷史不得自行恢復。

### 平台介面約束

介面變更遵守專案 `design.md`：禁止下拉框；圖像源使用單行橫向圖帶，標註與實測同列，方向鍵選圖。不得以全圖集載入、全專案歷史序列化阻塞本件結果呈現。算法運算時間與使用者實際等候時間需分別量測。
