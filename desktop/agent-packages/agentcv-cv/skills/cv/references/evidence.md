# 寫給人讀的節點文檔

`documentation` 是自由 Markdown，用於說明節點如何設計、為何這樣選擇，以及目前知道與不知道的部分。不要套固定三段或三欄，也不必逐參數寫一段。依節點複雜程度，自行決定段落、小標題、例子、表格和圖像。

讀者可能不懂算法。先交代要解決的具體問題，再連接可觀察的特徵與設計選擇。專有名詞第一次出現時用短句解釋，例如「殘差是預測位置和實際配對位置的差」。用少量重要數字支持說明，詳細數據仍保留在真實產物中。

以本體組織主線：人類說的物體、缺陷與關係，在這個節點具體指什麼？如何從影像定位各實體，怎麼確認找到的特徵屬於誰，又怎麼變成數值與判定？這些問題依節點需要自然串連，不變成固定章節、必填清單或每節配圖的規定。對共用預處理等節點，可用它提供的資訊及下游用途交代目的，不強行套缺陷文章。

找邊與辨識物體身份分開解釋。尤其遮擋、交疊與越界會改變內外順序；不能只靠「最外面的就是參考物體」、亮度或最強梯度替特徵命名。交代獨立支持、整體形狀與有來源的尺寸先驗如何限制候選；圖上區分可見測點、模型擬合與遮擋推估。身份或前提仍有歧義時如實保留，不能用漂亮輪廓補足缺失資訊。

關鍵算法敘述應有對得上的圖像。解釋掃描、剖面或候選峰時，可在原圖標出實際搜尋帶與取樣方向，再把對應灰階／梯度曲線放在下方；明示座標、單位、候選與採用位置。亮度峰與梯度峰不同，不同斜率取得的峰也不能冒充同一條剖面上的數值。已有合適正常與缺陷樣品時，用相同方法與尺度並排對照，幫助人理解選擇；固定來源與標註身份，不能為湊對比重命名未知樣品或虛構曲線。圖的數量由需要解釋的主張決定，仍不變成固定配額。

數值要連回圖中位置、單位、正負方向及實際判定規則。以程式為準核對門檻作用在哪一條分支，不把品質門檻、開發容差、物理公差和統計誤差混為一談。發現文字與實作不一致時明示差異；僅寫文檔不能悄悄改算法。

需要完整範例時參考 [歪斜與包含分析示範文章](node-documentation-example.md)：它從 lid 與 pkg 的實體關係走到定位、邊歸屬、遮擋推估、有號間距與實際分支，包含固定實測圖和互動原理示意。這是敘事參考，案例數值與章節數都不是其他節點的模板。

說明的是可核對的設計理由與取捨摘要，不是逐字內部思考。只寫確實做過的比較與試驗；工程預設、人工規格、資料推導和暫定選值如實區分。沒比較過就寫未比較，不能聲稱最優。自檢 PASS、格式正確或程式跑完，都不等於工業精度已驗證。

圖片按需要使用，不為湊欄位生成圖片。引用的真實圖與數據必須屬於對應工件和步驟，不能用舊工件或不相關輸出充數。示意圖標為示意。圖上數字、點位與主張應能回查實算來源；圖像保留在當前工件記憶體快取，切換後不冒充可用。

設計文章可按需使用自包含 HTML／SVG 圖解，格式與隔離限制見 [visual-explanations.md](visual-explanations.md)。固定案例截圖須明示歷史來源及不隨工件切換；僅在編寫案例時生成一次，不在每次檢測時重新編碼、寫 PNG 或複製整份原圖。引用 HALCON 等資料時連到實際查閱的官方頁面，解釋與本節點的關係；外部介紹不是本工件的實測或驗收，未查閱的影片不冒稱已核對。

節點文章按正常網頁閱讀：白底深色字、正文和圖表連續呈現，圖解自行採用清晰的淺色配色，不要求讀者逐個展開圖卡。圖解需自包含，能隨單一 HTML 匯出，在瀏覽器離線閱讀；提供適合列印／另存 PDF 的靜態初始狀態，重要結論不能只藏在滑桿互動裡。互動示意和實測圖都應保留來源或示意標示，PDF 只呈現列印時的狀態。

新方案節點或 `run_algorithm` 使用 `documentation` 字串。內部 SDK 例如：

```python
with step("locate", documentation="這一步先找出外框，讓後續測量跟隨工件位置。反光區可能產生多個候選；目前尚未測試遮擋情況。") as s:
    # actual computation and saved outputs
    s.set_output("status", measured_status)
```

僅修改目前方案的說明：`set_node_documentation(node_id=..., documentation=...)`。這不重跑算法，也不改寫歷史結果。舊 `justification` 會轉為連續文檔供閱讀；不需要重新填舊三欄。歷史記錄沒有的試驗不能補寫成既成事實，需要試驗就新增實算。

執行契約獨立於文檔：原樣傳回宿主的 `source`，用 `expected_outputs` 宣告真產物，實際 `save_image` / `save_json` 保存同名輸出。來源身份、圖像、數據、依賴與分類規則仍須核對；文檔段落或圖片數量不作執行門檻。
