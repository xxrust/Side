# 從試算到可驗證的方案

單張圖看起來合理，不代表跨樣本可靠。保留樣本的人工 OK / NG / 缺陷類型與來源；未標註圖片也可試算，但不能自製人工真值或由檔名、目前峰數反推規格。

量測與判定分開。人未提供公差時可輸出量測並發起諮詢，不能擅自添加UNKNOWN產品類別；缺標定時保留像素尺寸。像元尺寸、鏡頭倍率、binning、重採樣與裁切影響尺度，但理論比例不能冒充已驗證實測標定。不同成像配置的樣本需有明確關聯。擬合殘差不能直接當作尺寸或尺寸差的不確定度；尺寸比較需考慮邊緣定位、覆蓋、成像與共同誤差。沒有公差時報差值與已知精度限制，不因兩個擬合值接近就宣稱實體完全相等。

開發階段若人類已授權暫用參數或以既有良品建立基準，應將實際量測、定位品質與暫用規則接成可執行的判定。不要把「尚未獨立驗收／尚無毫米標定」寫成永遠為 false 的全局條件，使所有良品固定成未知；像素幾何可以在像素單位中驗證。正式驗收缺口與本件觀測不足分開記錄：只有本件確實缺少判定所需支持時才走規格所定的缺測／未知分支。這不授權猜公差、把真實失敗改為 PASS，或把開發回歸冒稱量產有效；未獲授權的規格仍須詢問人類。

參考資料僅在實際解析與讀取後才能聲稱使用；不能由3D檔名推定理解了幾何。工件、部件及關係由人提供或經核對，不預定任何命名。

局部優化與全流程優化要同時觀察上游誤差傳遞、缺失依賴與下游失效。先保存基準方案，在相同圖片集、成像配置與驗收條件下比較候選；不要只追求單步分數，卻讓全鏈誤拒或漏檢增加。保留混淆、規格聲明的未知與失效樣本，而非只展示成功例。

目檢已發現結果違反當前目的時，不以「可編譯、零故障」作為完成理由。例如需求是物件計數，而一個連通域包含兩個物件：保存連通域數與黏連證據，但繼續比較可分離物件的方法、逐個核對輪廓，再重跑全流程。不能改叫「候選數」就結束原計數需求，也不能放寬形狀門檻把黏連當作正確結果。若現有圖像確實不足以分辨，指出具體歧義並透過諮詢詢問工程師如何處置；不填假數字或宣稱精確數量。

程序更新後重跑代表性圖片集和已知反例。將開發探索樣本與獨立驗證樣本區分；調過參的圖片不自動變成獨立測試證據。報告需交代樣本覆蓋、缺口、閾值依據與失效處置，不用單一分數聲稱數學證明了所有場景。

重用歷史方案前核對目標、輸入分佈、成像與邊界是否相符。可重用程式、比較方法與適用經驗，不能繼承不相符圖片或版本的成功狀態。正式採用、人工驗收答案與發布由使用者決定；診斷、READY_FOR_REVIEW 或圖像顯示成功均不替代這些決策。

## 公開圖集批量驗證（真圖、GT 盲化）

使用 `desktop/scripts/agentcv-benchmark-batch.mjs` 的 `runBenchmarkBatch` 或 `--help`。它對每個樣本呼叫桌面同一個 `runAlgorithm` 與真實 Python/OpenCV runtime，保存 code/parameters/source binding、逐圖耗時、artifact、procedure trace、錯誤及可重跑命令；少量代表樣本保存可直接開啟的 `workspace.agentcv.json`，大量測試可 `--no-workspaces`。不能把直接執行獨立 Python 的成績稱為平台端到端成績。

預測輸入 manifest 用 `agentcv-blind-batch-1`，只含 dataset/split 字串與 `samples:[{id,images:[{path,role}]}]`。GT、人工 OK/NG、缺陷類型與 mask/bbox 真值只交給外層 scorer，不能給 predict。此為防止誤傳與便於審查的實驗隔離，**不是 Python 檔案安全沙箱**：必須另審程式、模型與輸入來源，不能聲稱任意程式無法讀 GT。正常訓練圖、訓練產生的模型可用，記錄它們的 SHA-256、訓練／校準／測試分割；測試 GT 不可用於選參。程式本身、模型來源、分割、參數固定後再測；有探索則如實標為開發結果。

每步仍要給節點文檔。方法需以本步輸入、輸出與失敗例支持；參數需比較真實候選或明說尚未比較及選擇來源；邊界需有實際 gate/反例與失效處置。批量不豁免三依據，`SUCCEEDED` 只指程式成功，`READY_FOR_REVIEW` 只指證據結構通過，都不是準確率或正式驗收。

Scorer 讀獨立真 GT，明列樣本數與公式：像素 IoU=TP/(TP+FP+FN)、F1=2TP/(2TP+FP+FN)；圖級準確率=(TP+TN)/N；bbox 需列 IoU 匹配閾值、一對一匹配方式及未配對框計數。說清空 mask 分母為零策略、macro/micro 聚合差異、UNKNOWN/失敗如何計入，保留失敗圖及疊圖，禁止用訓練損失、單張觀感或 evidenceAudit 代替 GT 分數。

## 多輪高目標迭代

開發比較、校準、獨立驗證及最終驗收分開記錄。每輪保存實際配置／程式 hash、同一開發子集的指標與 delta、真失敗圖；不得把不同子集的差值稱為方法提升。只有正常開發圖時，正常誤報與配準成功率可測，異常召回／缺陷像素 F1 仍未知，不能用正常指標代替。已評分或已看過失敗答案的測試集不能恢復「首次未見」資格；後續只能稱固定 benchmark 再驗收，另取未用資料才能支持新未見驗收。

選定方法後凍結實際 import 的程式、模型、配置、分割、輸入、三依據與輸出契約，再經真平台執行最終測試。可使用專案的 `benchmarks/iteration_guard.py freeze / run / verify` 保存時間、hash 與 dispatch ledger；重跑用 `--reproduce`，重訓／改參後不能冒稱相同凍結版本。此腳本只保護工作流與記錄，不是 Python 安全沙箱。未完成和故障必須在完整樣本分母或覆蓋率中獨列呈現；傳輸完整、程序成功、三依據完整與準確率達標各自驗證。多個傳統候選未達標只能支持本次已測路線的限制，不能據此證明所有傳統方法不可能或偷偷換用未授權的深度權重。

## 統計口徑與落地

run_dataset_scheme逐件執行，保存方案版本、輸入內容hash、參數、環境、狀態、結果、真耗時與產物ref。不要用重複引用同一圖的容量／速度測試宣稱獨立樣本準確率。

只有有來源且確認的人類答案可進獨立統計。perCategory為one-vs-rest TP/FP/FN/TN；precision=TP/(TP+FP)、completed-case recall=TP/(TP+FN)、FPR=FP/(FP+TN)。FAULT不進正常混淆矩陣，但必須列labelledFaults、unavailableExpected和coverage；endToEndDetectionRate把已知正例中無法完成的件也列入分母，不能只報完成件召回而隱藏故障。分母為0時值為null，不能顯示100%。Agent目檢是具體圖像核對紀錄，不是獨立人工GT。

圖像源statistics卡顯示真延遲分佈、回歸、逐類召回／誤判及故障。節拍、允許漏檢／誤拒、標註與成像覆蓋缺失時提出具體問題。未給節拍或未完成現場驗收時不能宣稱可落地；以重複小圖的Python啟動速度不可冒充相機產線性能。

分類守恆：sum(counts.categories)=正常完成分類件數；sum(counts.exits)=processed。每件恰一最終類，FAULT/CANCELLED為獨立系統出口，未派發的待檢件不混入已處理分母。多缺陷標籤不重複增加產品類別張數；若合計不符必須報錯，不能畫成看似合理的圖。

## 平台入口與回歸失敗

工具回報成功後，核對結果是否能從當前輸入／輸出視圖或明確的對話引用打開、是否綁定正確圖片，以及依據和候選是否能從現有入口讀取。保存成功不要求把每張產物都發布到畫板；只展示當前討論所需的關鍵圖。單獨渲染器或資料模型測試通過，不能證明人類實際可操作。頁面遷移後仍須保留圖像切換、候選採用、原圖比例、問詢及過期結果隔離等行為。

既有失敗只說明出現時間，不能證明不影響使用。逐項保留原始需求與失敗原因：先查目前UI/API是否缺少能力，再修功能或遷移失效測試。遷移時保留原始正確性與資料歸屬斷言；不得僅改成掛載孤立元件就宣稱畫板入口恢復。未修完的功能與未驗證的行為在checklist標為待完成，不混入已完成項。

來源計數與迭代必須使用同一個當前圖像源成員集合；固定參考只在該集合實際包含它時排除。圖片導入時的sourceId是歷史來源，不能覆蓋後續明確的卡片分組。回讀時若processed超過total，視為平台計數缺陷並保留原紀錄，修復後真實重跑，不能修改數字冒充完成。

完整流程的可讀性也屬交付條件：方案總圖須可從圖像源與固定參考，沿真實資料／條件連線走到分類規則與最終出口；節點內須顯示實際算子依賴與輸入輸出。只有程序列表、只有結果圖、或把父子包含關係當資料依賴，都不能視為完整流程。依保存的定義顯示所有可能分支，依選定工件的紀錄標示真正走過的路；缺少依賴資料時明示缺口，不能憑算子排列順序補造因果。
