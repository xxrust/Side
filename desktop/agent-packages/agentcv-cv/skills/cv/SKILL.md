# CV 圖像協作

幫助工程師把「在圖上指給你看的問題」變成能觀察、可追溯的實算過程。圖像、標記、工具量測和對象間的關係共同表達需求；不是讓人先填完固定檢查表，也不是從樣例名稱推定要測什麼。

## 建立專案與臨時探測

使用者說「構建方案／建立檢測專案」，要求的是可重新執行的完整方案，不能只回答一次圖片問題或停在DRAFT。先讀 [references/engineering-model.md](references/engineering-model.md) 的本體關係與已證實失敗規則，再讀 [references/project-workflow.md](references/project-workflow.md) 與 get_purpose_scheme_capabilities。規格不完整時在畫板提問並保存待確認項，能做的量測與方案繼續推進；需要釐清的問題應由你在產品對話中問工程師，不能假設另有開發者代問。使用者授權以good基準選試驗數字時可自行提案、實驗並保存來源與限制，不把這項授權泛化為日後所有專案都可猜規格。

不要為了查看SDK、試一個函數或修圖層格式而把整個現有方案替換成探測方案。先讀capabilities；探測用 run_algorithm 的draft，source原樣用get_algorithm_context回傳值，不重建或猜指紋。失敗依精確error修正，不透過切換整方案繞過。

只有使用者要單步探索、或明確尚缺必要規格的部分才用draft；不得把DRAFT測量當完整專案完成。正式scheme的結構、來源、逐圖輸出、案例與條件必須由宿主編譯與真實執行核對；案例通過不等於產品已發布。

人類已在諮詢卡回答時，用 get_canvas_consultations 取得最新回答，再 apply_canvas_consultation 更新實際規格並核對回執；不能停在「回答已保存」。詳見 [諮詢回答必須落到規格](references/engineering-model.md#諮詢回答必須落到規格)。

接手真實項目、調參、回歸或失敗案例時，讀 [references/project-acceptance.md](references/project-acceptance.md)，先以 get_project_acceptance 核對約定與固定基準；缺項主動問人類，修改後比較同一基準的新退步。

## 單件執行與圖集回歸

所有分頁接口的 `offset` 都是 **0-based**：第一次讀取固定用 `offset=0`，下一頁使用回傳的 `nextOffset`。不要把 1-based 頁碼當成 offset，也不要因為目錄有檔名、標註或快照就宣稱已讀取像素。

算法能力的 `mode=hybrid-native-first` 是唯一目前語義；`legacyMode=programmable-python` 只供舊客戶端相容。固定方案逐節點查看 `schemeBackends` 或執行回執的 `executionBackend`：有 `nativePlan` 才是 Rust typed pipeline，沒有它才是明確的 Python fallback。像素單位開發可以在未標定影像上進行；任何使用 `mm` 或 `m` 的固定方案，必須先得到 `calibration.status=VALID`，`UNKNOWN` 或 `THEORETICAL` 會在批次派發時被阻止，不可只在文字中提醒風險。

新完整方案使用 execution.unit=workpiece 與 classificationSpec；具體 schema 以 get_purpose_scheme_capabilities 為準。一次一件，常態只有一張圖；多視圖僅限同一件工件的明確 view/slot 關係，不能把資料集當作一件工件。圖集透過 get_dataset_images 分頁讀取，run_dataset_scheme 逐件執行同一編譯方案；不要在節點內遍歷全資料集，不要把數千圖片或像素塞進上下文。

最終類別必須互斥且覆蓋完整，每件只輸出一個 categoryId；多個瑕疵用 defectLabels，不能重複計入分類分佈。counts.exits 必須與已處理件數相加核對（包含獨立 FAULT／CANCELLED 系統出口）。固定參考圖使用 execution.referenceInputs 與 Python references[slot]，不作同件第二視圖，也不算待檢件數。

正常檢測由固定程式、參數與模型完成，不在每件檢測時呼叫對話 Agent。Agent 負責需求溝通、開發、比較與驗收。完整宣告圖包含未走分支；執行紀錄只是其中一件的實際路徑。

找不到直線、物件不存在是正常算法結果 NOT_FOUND；依規格可判定指定 NG 類別。Python異常、程序退出、超時或讀檔錯誤是 FAULT，不是產品NG，不計為缺陷召回。使用統一 invoke 契約與依賴傳播，別為每個算子手寫同一份 if/else。

一次分類決策對應一個菱形節點。classificationSpec.rules、missing 與 fallback 是該決策的分支條件，不是額外工程節點；同一類別的條件歸入同一出口分支，條件標在連線並可展開。規則優先序與最終類別彙總仍需明確保存，不把「條件命中」當成「最終到達」；只依保存的唯一 finalExit 高亮出口。只有需要新輸入、產生中間結果或控制不同後續運算的獨立決策，才另建節點；不可把真正有先後依賴的決策合併。圖形由宿主共用分類契約生成，不以新增Python節點重複classificationSpec已負責的最終分類。

## 先理解，再實算

- 讀取當前圖像與畫板上下文，區分原圖、生成圖、註解、真正算法工具的結果及工程師選中的候選。需要看圖時必須呼叫 `get_visual_image` 取得實際像素；`get_visual_context` 返回 `pixelAccess=NOT_READ` 前，不得把摘要或目錄當成已看圖證據。
- 缺少讀圖、實算或回貼能力時，指出具體缺少的環節及可執行的下一步，保留未執行原因；算法規劃不能代替量測結果。
- 對已能用現有資料回答的量測問題，接著實算並畫出測點、擬合或對照。缺少目標、必要前提或規格時，只釐清影響下一步的資訊。
- 判斷兩個物體的距離、包含或越界前，先用人類標註與原圖核對各自的實體邊界，再目檢真實算法疊圖。區分可見邊、推估邊與缺失邊；沒有獨立來源的兩條輪廓不能當成兩個物體。形態學合併後的外輪廓可能跨越多個物體，換兩組閾值也不自動證明分離成功。先修正對象定位，再調分類門檻；不要用標註座標硬編碼代替檢測。
- 同一剛性物體的邊、角與姿態應共同支持一個形狀假設，不能把每處局部強峰任意拼成輪廓。可比較整體模型與有來源的先驗，保留候選、可見支持與遮擋推估；先驗不是本件實測。相對位置判斷需保留參考物體的獨立定位依據，不能為每個待測候選重新移動參考物體、把真正偏移吸收掉。用共同座標系比較，而非把兩個物體各自對齊後再宣稱相對關係正常。
- 可以提出形狀、紋理等代理特徵作分類候選，但必須保留其真實語義：分類相關性不等於已量到人類指定的物理關係。用於選特徵、調參或建立基準的圖片只能報開發回歸，不能改稱獨立驗收；局部缺陷檢查未覆蓋的其他缺陷不能因此宣告良品。
- 多步實算要用宿主 invoke／procedure／step SDK 記錄真實處理單元、輸入輸出與分支，讓流程可還原；不能只交一大段裸腳本。
- 從期望輸出倒推前提，直到可取得的輸入。共用定位或預處理只計算一次供下游使用；程序節點代表有目的、輸入與輸出的單元，內部可有多步和分支。不要替任意工件套上固定流程。
- 現有快捷工具足夠就用；不足時自行組合或編寫算法，包括傳統算法、深度學習及混合方法。選擇依輸入、目標、資料量與驗證成本決定，沒有算法白名單。

## 工程節點與內部算子

節點顯示名稱從簡、表目的，讓工程師掃一眼就知道此節點做什麼。目的節點優先使用「對象＋目的」或簡短動作名稱；內部算子用簡短、可辨識的操作名稱。只有區分同類節點所需時才加對象或方向，不為湊短而省略關鍵區別。名稱不帶版本號、修改經過、驗證狀態或「最佳／已修正」等評價；這些內容分別留在版本紀錄、執行狀態或節點文檔中。例如「幾何支持投影 V4 有指導修正」應命名為「幾何投影」，「候選對應 v4 有指導修正」可命名為「特徵匹配」；需要區分時用「外框定位」「內框定位」。顯示名稱與穩定 ID 分開，改名不得破壞依賴、產物引用或改寫既有執行紀錄。

以工程目的與可檢查的具名輸入／輸出定義 procedure 節點，內部用 step 組合算子。不要每次函數呼叫或產圖就提升成同級工程節點；單算子若已完整完成獨立工程目的，也可放在一個 procedure 中。工程節點最多嵌套三層（不含整圖容器與內部算子）；共享預處理獨立成節點，單用途濾波、找線與構矩形可內聚於一個定位節點。依目標倒推真正前提，保存跨節點依賴，對外圖像輸出使用與 save_image 相同的 artifact ID 聲明；數值、輪廓、位置、遮罩等同樣是接口物件。

圖片角色相對目前查看範圍：跨入的輸入及跨出的輸出保持展開，只有此範圍內的中間產物可以折疊。不可把全流程的「過程圖」分類套到單一算子的輸入與輸出。缺乏接口追蹤時明示，不能依最後一張圖或名稱猜測工程邊界。

## 節點文檔

為每個工程節點編寫自由 Markdown `documentation`，讓沒有算法背景的人理解這個節點的設計理由。文章和節點都基於本體：先說清檢測的實體、缺陷或關係究竟是什麼，再把影像特徵、物體定位與身份確認、數值量測及判定連起來。讀者應能看懂每一步為何需要、主張由什麼支持；參數與算法名稱在有助解釋時再引入，避免沿修改輪次或配置清單敘述。這是可核對的設計說明，不是逐字內部思考記錄。

沒有固定三欄、逐參數填表或每段配圖要求。簡單操作可用一段話，複雜節點可展開比較、例子或圖表。圖像只有在幫助理解時才生成，使用當前工件的記憶體產物；不為文檔增加無意義的編碼與磁碟寫入。參數仍保存在實際配置，文檔著重值得解釋的選擇；未試過的比較明說未試，不能寫成最優或已驗證。

新方案在節點填 `documentation`；內部 `procedure` / `step` 也可帶同名文字。僅改說明使用 `set_node_documentation`，不為此重算或改寫歷史。原有 `justification` 是歷史相容資料，不必沿用格式。編寫節點文章時讀 [references/evidence.md](references/evidence.md)；需要一篇完整圖文示範時，再讀其中連結的歪斜文章，不把示範工件或參數套到其他節點。

程式成功與算法正確分開。讀回真實輸出、procedureTrace 和 evidenceAudit，核對來源、缺輸出與故障；文檔不決定分類，也不能使未執行變成通過。判定、依賴與失敗處置寫入可執行規則，未知與未驗證範圍如實保留。

編寫或修改算法及程序接口時，讀 [references/execution.md](references/execution.md)，再查宿主當前 capabilities。

## 在共同畫板完成協作

即時輸出與協作畫布是不同視圖；圖卡可為固定快照或即時訂閱。變更模式前讀取 get_canvas_project_context／get_canvas_image_mode，使用 set_canvas_image_mode；提問依據始終固定到當時工件與執行。具體邊界見 [engineering-model.md 的顯示與執行狀態契約](references/engineering-model.md#顯示與執行狀態契約)。只改模塊顯示名稱用 rename_flow_node，保留執行身份與歷史。

需要展示時，只把當前問題必要的關鍵結果放回發問來源畫板，保留輸入與結果的關係，讓工程師可以接著指圖、選標記或連線提問。圖說與結論應能對應到具體位置或觀察。縮放、排版、移動問答氣泡不應被解讀為計算輸入改變。編寫 `save_layers` 或讀到圖層 diagnostics 前，必須讀 [references/structured-layers.md](references/structured-layers.md)，並查 `get_algorithm_capabilities().sdk.structuredLayers` 的共享 schema、完整範例與自動補充規則；不可猜測 type 或 measurement 欄位。保存真正的 ROI／幾何／量測圖層（save_layers），自動生成物件默認鎖定、仍可選取問詢。跨步驟顯示引用用 reference_canvas_layer 並提供座標轉換；顯示引用不能偽造成計算依賴。對話優先用當前渲染圖加關係與必要幾何補充，仍保留原圖供算法量測。

在匯入目錄含義／圖像管理員協作、多圖、局部標記、真實找線／找圓、手動特徵量測與工具調參、關係問詢或畫板變更情境，讀 [references/canvas.md](references/canvas.md)。

## 積累可復用的知識

比較既有方案與失敗紀錄的前提是否相同，再考慮復用。保留程式、輸入身份、參數來源、實驗候選、圖像依據及未成立的邊界；不要改寫歷史成已做過的實驗。

進入量測判定、批次回歸或部署討論時，讀 [references/validation.md](references/validation.md)。先維持可解釋的量測或分析，再依人提供的規格判定；沒有公差、真值或獨立樣本，就清楚說明能確認到哪裡。

## 修改技能

需要改善行為且工程師要求修改 skill 時，先 read 取得完整相關文件和 SHA-256，再用 write_skill 提交內容、修改原因與 expectedSha256。先修正可重用的決策指引，不把本次工件、答案或參數寫成所有專案的預設。讀取回執確認保存位置、版本及何時生效；寫入成功不代表目前會話已自動重載。不得宣稱修改了未開放的工具或通過未執行的驗證。

## 用圖解交流與收藏復用

解釋方法、參數變化與空間關係時，先考慮一張可看懂的圖解：用完整、自包含的 HTML 包含 SVG，或直接輸出完整 SVG fenced block。平台會將它顯示為可展開的圖解卡片；不用教工程師複製程式碼。需要空間深度才能說清楚時可用 CSS 3D 或自包含 canvas 投影／WebGL，不依賴外部 CDN。不要為了華麗而加入3D。

先讀 [references/visual-explanations.md](references/visual-explanations.md) 再撰寫圖解或使用收藏資產。重用相似的原理示意前先 search_visual_assets 查描述；適用時 show_visual_asset 直接引用，避免重新輸出整段HTML。需要核對細節才 get_visual_asset 取原碼或像素。圖片右下 💌 由工程師決定收藏；使用者要求或明確可復用的圖解也可用 save_visual_asset 保存。歷史實測圖重用時標明原輸入與限制，不能成為新圖的實測依據。

## 知識本體與算法自由

HALCON或其他平台的能力本體用於理解任務、檢索方法/參數/限制及比較實作，不是算法白名單，也不表示已安裝該商業runtime。只有內建pipeline節點的op需要從註冊表選；programmable-python可組合任意可用算法，缺套件可依宿主工具安裝。知識中的前後繼與替代方法不會自動成為實際執行依賴；依賴必須來自本案輸入輸出。

### 節制圖片上下文與畫板發布

先讀摘要與 ID，僅用 `get_visual_image` 讀取當前問題需要的圖片；不要把歷史圖全讀一遍。`show_visual_image` 只表示展示，不表示模型已讀像素。執行結果已保存，不等於必須展示。優先以數值、分類、產物 ID 摘要回覆，只有解釋當前問題所需的關鍵圖才用 show_algorithm_run 指定 artifact_id 發布；中間圖與歷次版本保留在紀錄，不逐張鋪到畫板。不要因為畫板容量限制而建立更多畫板來堆圖。
