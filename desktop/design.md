# AgentCV 介面與響應設計約束

本文件是介面實作與驗收依據（2026-11-04，使用者明確要求）。

- 全軟體禁止下拉框，包括原生 select 與換皮的下拉選單。少量選項使用直接可見的分段按鈕；大量項目用可搜尋、可捲動的清單或圖帶。既有頁面改動時必須一併清除下拉框，不得新增。
- 圖像源以圖為主；卡片圖區至少占 80%，容器尺寸固定，不隨相機比例、載入狀態或結果有無跳動。圖片保持原始比例，不裁掉檢測內容。
- 圖像源圖集名稱與操作放在緊湊標題列。可選圖為單行、多列、橫向捲動圖帶，不做多排縮圖或分頁。千張以上使用視窗化，只建立可見附近的縮圖。
- 每張圖的「標註」與「實測」並列同一行；人工答案與真實執行結果來源分開，但不浪費額外一行。長文字省略並提供完整提示。
- 左右方向鍵選擇前後圖片，選哪張執行哪張。輸入文字、IME 組字和修飾鍵組合不觸發選圖；執行中不偷偷追加重複任務。自動切換不覆蓋人工選擇。
- 原圖先顯示；結果完成且來源核對通過後立即呈現。不得把整個專案存檔、Git 快照、全圖集縮圖或無關歷史整理放入呈現結果的關鍵路徑。
- 桌面常駐執行傳遞經驗證的原始資產引用，避免每次跨橋傳送原圖 Base64。輸出按需讀取，避免為顯示一張圖傳送所有圖。
- 驗收分別量測點擊至原圖、原生執行、傳輸、結果解碼與可見時間。算子時間不能冒充端到端響應時間；測試橋接時間不得冒充原生桌面時間。

現存其他頁面的下拉框仍需逐頁遷移；本規範不代表已完成全站清除。

## 圖像源驗收補充（2026-11-04）

- 縮圖下禁止顯示檔名；檔名只在目前圖片的視窗右上角顯示，縮圖可用 hover/無障礙名稱查詢。標註、實測只留一行。
- 縮圖圖片區至少占卡片高度的 80%，大圖區使用扣除必要工具列及單行圖帶後的全部空間。禁止固定小圖高度加大片留白。容器放大時圖片區同步增大。
- 分類顏色從高區分度色盤依序分配，不可直接對分類名稱雜湊成色相（相鄰類別會撞到相近藍色）。顏色之外仍保留名稱與選中邊框。
- 虛擬圖帶的外部捲動容器、總寬度必須穩定，更新可見項目時不得先清空容器造成 scrollWidth 縮短；需實測拖拉滑塊、觸控板、方向鍵並核對位置不跳回。
- 主畫面只呈現原圖、判定圖、簡潔的分類結果。隱藏 state/metric/runId、規則表達式、重複原因、內部追蹤文字；這些仍保留在資料中，不作為主畫面文案。只有多張依據圖時才顯示切換控制。
- 截圖驗收必須檢查圖片佔比、對齊、捲動與實際視窗；不能只以 DOM 數量或測試通過當作品質合格。

## 即時執行更新（2026-11-05）

- 執行進度與圖片載入完成不得清空整個畫板面板。標題、工具列、輸入／輸出卡片與 viewport 必須保留同一 DOM 元素；只更新變動欄位及圖片 src。
- 未執行、執行中、完成、失敗沿用同一框架。等待時清除舊結果的 src 並隱藏圖片，不能把其他工件的圖當作本件輸出，也不能為了等待提示移除框架。
- 無變動時不重讀原圖、不重建輸入選擇器；圖片解碼完成只更新圖像。需驗證靜態元素身份與移除次數，不能只以肉眼無閃爍判定。

## Agent 圖片上下文與畫板發布

- 一般對話引用畫板只傳摘要與穩定 ID，不自動渲染整板或重送歷史像素。Agent 用 get_visual_image 按需讀取。
- 明確圖像提問最多直接附 4 張；更大的集合先傳摘要。不要同時附整板合成圖與各張原圖。
- Codex 同一對話中已送出的相同像素不重複附送；標註變更後的渲染圖視為新圖片。
- 實算保存與畫板發布分開：算法、批量與完整方案執行不自動堆圖片。需要展示才明確選取產物發布。
- 保留歷史紀錄與原始產物，不能為減少上下文而刪除人類資料。
- 保存專案、Git 試算與工作階段使用同一序列化規則。同一資產的相容欄位不得重複保存相同 base64；不得靠提高容量上限或刪除唯一像素內容掩蓋膨脹。
- 圖片 ID 與目錄來源 ID 分開校驗；錯誤回饋指向具體的 metadata 查詢，不引導 Agent 重送整批圖片。

## 千張級批次產物保留（2026-11-06）

- 一次方案執行以「一個工件」為單位。算子細節中看到的 15 張，是該工件／該次執行的產物集合；不能把它當成資料集總數，也不能在批次中把全部工件的圖像一次載入介面。
- 1000 張批次必須為每件保存分類、量測、故障／正常狀態、來源指紋、方案指紋、每個算子耗時、完整週期耗時與產物摘要。這些資料用分頁／聚合統計讀取，不能靠載入 1000 件完整 run。
- 單件互動檢視使用 `artifactRetention.mode=all`。批次預設使用 `diagnostic`：保留故障、不良／待定、首尾及定期樣本的圖像像素，其餘圖像保留尺寸、雜湊、角色、來源與 `metadata-only` 狀態；不把不可載回的圖顯示成可用圖。
- 批次不自動把過程圖發布到畫板，也不把每件的 base64 帶入專案或 Agent 上下文。需要看某件圖時，先用單件記錄／引用明確載入；需要全量像素才由人類選擇完整保留策略。
- 單件持久化完成 CAS 寫入後，才清理該件的暫存 `algorithm-runs/<run>` 目錄；清理只允許已知運算根目錄的直接子目錄，不能用寬鬆前綴刪除，也不能在保存失敗前清理。這避免 1000 件批次留下 1000×節點×產物的暫存檔。
- 任何報表都要分開顯示「件數／分類與耗時事實」和「可查看像素的證據件數」。15 × 1000 的潛在產物量必須在執行摘要中可見，避免把抽樣圖誤稱為全量證據。

- 圖像管理員與其他專用 Agent 不得生成硬編碼的助理開場或失敗備援回覆；載入／錯誤是系統狀態，只有真實模型文字才進入對話。
- 專用 Agent 跟隨所選執行器及其帳戶，模型設定獨立；不得悄悄讀另一執行器憑證、切換模型或偽造完成。
- 所有 Agent 入口共用執行器初始化與升級邏輯；匯入恢復或管理員先啟動，不能因此使用尚未遷移的舊帳戶。一次性升級後保留使用者明確的執行器選擇。

- 管理員詢問分類含義後，人類確認即應產生待確認草案卡片；不得要求人類重複下達「整理」指令。產生草案與正式套用仍是兩個狀態。

## 專案入口與本機交付（2026-11-05）

- 「開啟專案」直接選專案文件，不先要求使用者理解資料夾／JSON 格式。`.agentcv` 是包含原圖、紀錄與 Git/LFS 的文件包；macOS 註冊為可辨識、可雙擊的專案類型。
- 選到既有 `manifest.agentcv.json` 時，宿主自動載入其所屬專案及相對資產；不得將內部清單直接送入舊版 JSON 模型。舊 JSON 仍可開啟。
- 雙擊文件的冷啟動請求須等工作階段恢復完成；運算中先排隊，未保存內容仍走正常確認，不能靜默丟失。
- 保存已開啟專案不再次詢問層層目錄；新專案一次選名稱與保存位置。
- 本機正式打包交付到儲存庫根目錄 `AgentCV.app`，保留可回復的舊包。不得原地覆寫正在運行的 bundle；遇到使用中先準備待替換包並明示狀態。

## 原位問答與即時畫面（2026-11-05）

- 節點／整個流程的「詢問」入口，必須在當前可見表面開啟並聚焦編輯器。即時輸出模式不能隱藏問答；放大流程圖內的提問必須進入同一個 modal，收合後回到輸出面板。
- 圖像快速刷新與問答同步分開。保留輸入／輸出、靜態標題及正在輸入的 textarea，不以重建整個畫面修復對話不可見；焦點、游標、草稿和多輪歷史必須保留。
- 切換問題使用可橫向捲動的按鈕，不新增下拉框。節點問題與圖像／連線問題的引用類型不能相互借用。
- 發送前的引用擷取失敗、連線失敗都要在原問答框顯示原因，文字可重試；不得只留下全域提示，也不得製造 Agent 回覆。
- 使用者明確引用的流程節點、表格及標記，必須保留在第一輪送出的文字中；一般專案摘要不得刪除 reference，也不能依賴後續歷史回填補救。
- 流程問答只擷取完整結構與當輪流程圖；建立空的圖像快照，不先複製整板像素再丟棄。核對實際送出的圖片數及同一問題的執行會話。
- 驗收涵蓋輸出模式、畫布模式、放大流程、右鍵連線、中文組字、Enter／Shift+Enter、失敗重試、關閉再開與多輪接續。DOM 與真模型通路驗證仍不能替代原生桌面操作驗收。
