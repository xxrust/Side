# 检测完成与后台归档：用户确认的重构契约

2026-11-12。依据用户从 Side 讨论交接的两条明确指令。本文记录新的实现方向；并非完成证明。旧版 `framework-performance-contract.md` 和旧测试结果保留，不能把两种边界的数字混称为同一指标。

## 实时检测

2026-11-12 最新目标：真实 Windows 桌面中，每个热样本从 Execute 点击到检测完成不超过 150 ms，且该周期扣除实际算法独占时间后不超过 50 ms。两项须同时满足；均值达标不能代替逐样本达标，归档完成仍须单独验证。保持既有算法源码、参数和测量结果；运行环境、线程调度及框架链路可以优化。

保留 Rust 主框架、现有算法源码和参数。普通检测不生成阶段 PNG；原图、节点像素和输出图由计算侧在内存中持有，节点传递受控引用，界面只取得当前需要显示的结果。阶段 PNG 仅在用户显式调试时生成。

减少同一图像、大结果树的重复传递、复制、编码、解析。优先改整段执行链，不以零点几毫秒的局部改动代替架构调整。Python/OpenCV 中的算法实际计算不在本次改写范围。

检测完成必须具有当前工件的有效分类或明确故障、当前输入/内存输出图、恢复的操作控件，以及实际呈现。自动切图、RGB、缩放/最大化、停止、主 Agent 节点询问与历史读取均须在真实 Windows 桌面验证。

检测完成不等待逐件磁盘同步提交。接口和界面必须准确区分“检测完成、待归档”“归档完成”“归档失败”。禁止把内存队列接收称为已经持久化。

## 后台归档

检测记录按数量或时间批量保存。队列必须同时限制件数和字节数；入队时取得不可变事实与精确产物字节的所有权或租约，不能依赖随后会被四组资源缓存淘汰的临时句柄。队列满时明确背压或停止继续采集，不能无限增大内存或静默丢记录。

每件记录保持执行、工件、方案、输入来源身份。实际写入成功后才发布持久化引用；写入失败保留待处理记录并显示错误。项目切换不能把旧任务的结果挂到新项目。关闭软件必须有明确的等待归档或放弃待归档记录行为；停止检测与停止归档须有清楚语义。

保留算法产物原始字节和哈希、完整测量事实、历史重开、另存为与撤销边界。批量策略需要验证超时刷新、数量刷新、手动刷新、失败恢复、关闭排空及队列上限。普通阶段图像的像素不因归档默认写成 PNG。

## 分开测量

每轮必须同时报告：

- 检测完成：真实 Execute 点击到分类/故障、控件可用、当前图像解码显示和两帧呈现；框架开销扣除实际算法独占时间，目标仍为每个热样本低于 50 ms。
- 归档完成：入队到真实持久化确认，报告批次大小、等待时间、写入时间、积压件数/字节和错误。
- 完整完成：同次点击到该件归档和显示都完成。与旧“同步落盘加两帧”结果并列，明确批量等待已改变，不能声称同边界提速。

原有 20261112-214143-154832 为旧边界：23 个热样本框架平均 266.6245 ms，范围 195.9680–364.2315 ms，功能通过、性能失败。此前 094828 为 242.3467 ms，不以跨轮次波动断言某项优化的收益。

SDK 时间含图像处理、输出校验、编码和追踪，不能全部称为磁盘写入。桥接间隔含调度和应用处理，不能全部称为传输或归因于 WebView。20 ms 等数字尚无证据支持。

## 当前实现状态

用户方向已确认，后台批量归档尚未实现。原普通 inspection 已使用内存像素与 BMP 预览，但仍有每节点私有可写输入文件、结果树重复处理和逐件同步结构化记录保存。必须保持公开 SDK 文件路径的可写隔离语义；移除文件或改为延迟物化前，先建立兼容契约和真实算法验证。

测试资料不再默认每次整份保留。测试资料、WebView 缓存和临时目录改到 E 盘；保留最新验证结果和必要失败证据，旧副本采用明确保留清单清理。C 盘的独立 QA AppData 入口只允许指向受控 E 盘目标的目录连接。
