## 已实现并验证

- Rust/Python 常驻二进制分帧传输、不可变内存资源及原生图片 URL；普通检测不写阶段 PNG。
- Python 字节码缓存保持每次执行的新命名空间及真实嵌套异常路径；对象节点编译由约 11 ms 降至约 0.3–0.7 ms。
- 常驻进程只在启动时准备环境；显示 BMP 直接使用 BGR 编码，避免整帧 RGB 与 Pillow 中转。
- Windows 显示 BMP 使用页文件共享映射，Rust 读取并保留不可变字节；控制及报告仍走常驻通道，其他平台保留原有分帧路径。
- 原生执行事实以不可变 JSON 树保留在同一工件资源预算内；工程保存直接借用经过身份校验的树，在序列化时过滤内联图像字段，避免完整还原复制及单独递归遍历。产物字节同样借用原缓冲区，持久化完成后才确认。
- 已完成工件的结果摘要也采用不可变 JSON，撤销快照共享这些事实；批次计数、进度及界面耗时仍可更新，续跑复制批次状态后再替换，保留续跑前的撤销边界。
- 保存 JSON 产物时传精确字节引用，历史记录读取时还原相同的 artifact.data；避免约 640 KB 的重复传输。
- 持久化运行在线程池中并等待真实提交，新增内部计时，未把保存完成条件移到计时范围外。
- 一条命令完成隔离 QA 构建、启动、测量、回归与自动失败判定。
- 原生调度模块 `inspection_session.rs` 与实际前端调度模块做同输入差异检查；
  父子生命周期、分支、替代前提、故障、缺失产物和取消共 1,776 组一致。
- 原生输出契约模块 `output_contract.rs` 校验实际类型、坐标来源、尺寸、单位、有限值、几何与变换；
  与前端契约检查使用同输入对照。具体数量见本轮 `native-session-parity.json`。

当前桌面通过一次 `execute_inspection_session` 调用执行整件图；Rust 连续调度节点，
在下游消费前校验实际输出契约。进度带会话、执行、工件身份和单调序号，取消直接通知原生会话。
前端的算法请求准备与结果导入已拆开，保留原有来源和审计检查；本轮 Rust 会话完成节点编排、完整运行元数据、证据审计、分类、人工标签回归和保留决策，并在返回前等待实际持久化确认。前端采用原生结果，与生产 JS 实现逐项对照；桌面探针逐件回读实际磁盘记录，核对完整工件语义、所有运行字段、原始产物和完整收据，同时确认正常链路没有另发前端保存命令。持久化已计入 nativeSession，独占账本从原生准备区间扣除同一提交耗时并单独列入保存，外层验收时长不作扣除。持久记录保存提交前已知的原生事实和计时；后续前端核对标记及界面发布耗时只在实际导入后的记录和执行摘要中存在。仍需依据完整实测判断性能，不能将架构迁移本身当作提速证明。
Python 的 JSON 上游由同件常驻进程保留的精确字节重建独立可写对象，避免将完整解析值再传回 Python。
这些架构修改不代表已经达到 50 ms。

当前桌面回归通过：原图与内存输出图、RGB、等大图框、缩放与最大化恢复、询问进入已有主 Agent 草稿、自动导航、Esc/按钮停止、显式调试 PNG、历史 JSON 原始字节及解析值回读。
重复运行的 Rust 资源缓存不超过 4 个工件组/192 MB，字节码缓存不超过 32 项/4 MB 源码。
窗口监测没有捕获控制台弹窗；各计时组前后额外核验真实 Win32 主窗口可见、未最小化且未被系统隐藏。本次 QA 已正常退出。

本轮桌面历史载荷检查通过：对当前图片的 9 条非当前执行记录设置读取守卫，流程刷新及实际界面 render 均未读取它们的程序追踪或产物载荷；当前工件、执行和根节点保持一致。


方案指纹缓存按完整规范化内容匹配，限制为 16 项及 2M 字符，不依赖可修改对象的身份。
