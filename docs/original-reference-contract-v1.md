# 原图引用与输入文件契约 v1

依据：用户 2026-11-12 明确要求，原图只保留来源引用与身份，检测、节点与归档不复制原图。该要求优先于旧 SDK 无条件提供可写输入副本的默认行为。

普通检测使用原图的内存快照和独立可写算法数组。`image_records[i].path` 默认为 `null`，`fileStatus` 为 `NOT_MATERIALIZED`，不创建输入目录或 `.original` 文件。原始来源位置只作为 `sourceRef` 身份信息，不作为可写工作文件暴露。显示原图与内存输出图不依赖临时文件。

确有文件接口的算法必须主动调用 `input_file(index=0)`。该调用是显式请求临时可写输入文件，按需生成本次调用专有副本，更新对应记录的 `path` 与 `fileStatus=EXPLICIT_TEMPORARY_COPY`，并继续遵循已有执行目录清理规则。它不归档原图，不修改源文件，也不承诺永久回放。未调用的其他节点和输入不得产生副本。

当前非 inspection 的旧试验接口暂保留旧行为，用于兼容历史算法；普通检测不能因兼容自动回退到复制。原算法直接使用 `Path(image_records[i]['path'])` 时应明确报错并指引主动请求，不静默生成副本。

外部原图的持久引用必须包含来源与已确认的内容身份。源缺失、源身份不符、实时帧像素过期分别标记；不能用同名新文件或新帧冒充旧像素。现有工程已拥有的原图资产直接引用，不复制到每个执行目录。

本契约分阶段实现。首先取消普通检测每节点临时输入副本；外部导入引用、历史重新定位、相机帧可用状态及精简记录仍需独立实现和 Windows 桌面验证。不能凭 SDK 单测声称全部存储设计已完成。

验收保留原算法判定、关键量测、输出像素、RGB、图片切换与历史含义；普通检测无输入副本，显式请求后源字节与其他节点仍不受修改影响。旧的可写副本测试转为显式请求，原隔离断言保留，并新增默认无文件断言。
