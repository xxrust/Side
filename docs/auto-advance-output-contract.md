# 自动切换后的输入输出显示

“自动切换”只为下一次执行准备图片。一次执行完成后，主界面的本步实际输入、输出图、翻页和询问引用仍属于刚完成的同一工件；即使下一张图片已有历史结果，也不能切换成那次旧结果。

保留身份只存在于进程内，记录工程数据身份、工程代数、方案指纹、执行 ID、工件 ID、已完成图片、下一张图片与选图修订号。它不复制执行结果或增加图像缓存。选图通知发出前建立身份，避免面板先变空再恢复。

手动选图（包括重新选择已准备好的同一张图片）、切换工程或修改执行方案后，不再采用该保留身份。自动切换原有的取消、故障、批次、固定参考图、筛选和用户选图竞争保护继续生效。

连续执行时，进程保留一件已完成工件的记录与运行引用，供下一件尚未产生所选节点输出时显示。输入、输出和询问仍绑定这件已完成工件，状态标明“下一件检测中”。下一件的验证、分类和保存通过后替换该显示，并释放上一件缓存；开始运算本身不能清空上一件的像素。该状态不写入工程，也不累积整组图像。

流程图在自动切换后也采用同一件已完成工件的完整记录和运行引用，保留各节点实际耗时。连续运行时保留当前运行状态；尚无新计时的等待、运行节点可暂显示上一件对应节点的实测耗时，提示注明来源，取得本节点新计时后更新。跳过的分支不借用上一件耗时，缺失的实测时间不伪造为零。手动选图、修改方案和显式历史运行选择仍按各自身份处理。

图像源窗口也显示已完成工件的原图和判定依据，自动准备下一张不会让窗口跳到下一张的历史摘要。连续执行期间按已完成的执行与工件身份更新依据，不因下一件的进度通知反复清空图片。当前工件的依据直接使用刚验证的记录与像素，历史记录缺少像素时显示真实原因。

记录回载应核对输出模型的工件图片；异步加载守卫仍监视当前选图。当前选图可能已经是下一张，不能用它代替被展示结果的工件身份。

切换采用“准备、解码、成对提交”：新原图和输出图先在脱离可见 DOM 的图片元素中完成读取与解码，两者都具有有效像素后，在同一个同步任务中替换显示及引用身份。图像源窗口的原图与判定依据图遵守同一规则。等待期间不清空图片、不重置相机；读取失败保留上一组图片并显示错误，过期请求不得提交。原生执行的 `VALID` 状态也可能早于运行记录和像素交接，任何缺少替换像素的状态都必须保留旧画面。新工件没有输出或发生故障时明确说明原因及当前图片属于上次完整画面，不能伪装为新工件的成功输出。

回归检查运行：

```powershell
cd desktop
node --test qa/node-output-memory.test.mjs
```

测试生成真实图片并调用本机 Python/OpenCV，覆盖内存像素、自动换图的所有通知、循环到已有历史结果的图片、下一次执行、方案变化、手动选图、工程清空、记录回载，以及完整应用 DOM 中的输入输出、翻页、引用身份和面板重建。连续执行回归保持图像源窗口打开，核对每件计算期间与完成后的成对图片、实际图像解码、依据运行身份和自动切换开关。Python 默认使用 PATH 中的 `python`，可通过 `AGENTCV_QA_PYTHON` 指定。

慢加载回归分别阻塞原图读取与真实输出图解码，断言等待期间仍是原来的可见 DOM 图片、有效像素、相机位置和工件引用；只有两侧都就绪后才能提交。同时覆盖原图读取失败和被后续选图取代的旧请求。

旧的自动换图测试主要核对待执行图片是否前进，输出测试主要核对手动选图时是否清空；两组分别通过不能证明它们组合后的行为正确。上述测试直接覆盖“执行完成 → 自动准备下一张 → 输出继续可用”的连续流程，且不依赖本机历史审计目录。DOM 测试不等同于真实桌面的布局与窗口验收。
