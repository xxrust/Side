## 原型格式

8 字节魔数 ACVPAK01、8 字节小端索引长度、UTF-8 JSON 索引、依次排列的原始资产字节。
索引保留原始 $asset、mime、sha256、size，另存相对有效载荷起点的 offset。
按内容地址排序，重复引用仅存一次；偏移须连续且覆盖全部有效载荷。
容器本身是普通 application/octet-stream CAS 文件，拥有独立 SHA-256。
索引最多 4096 项/4 MiB，完整容器最多 128 MiB。这不是已发布的工程格式。

同时核对物理容器身份与每个逻辑资产身份。即使重新计算篡改后的容器哈希，也须拒绝逻辑哈希不符、越界、重叠、重复或尾部数据。
局部测试尚不构成完整工件事务的崩溃恢复或断电证明。

## 当前生产接入

生产路径保留普通 CAS 工件记录，仅把运行产物与代码按批次打包。至少 3 个新逻辑资产、原始字节合计至少 64 KiB、最多 4096 项且预留 4 MiB 索引后仍在 128 MiB 预算内，才选择容器；其余继续走原普通 CAS。选择发生在编码前，编码或内容损坏不会触发静默回退。生产索引版本为 agentcv-asset-pack-1，以包含 MIME 的完整逻辑身份排序，允许相同二进制内容以不同的 .bin MIME 描述存在。
逻辑描述符保留原始四个身份字段，增加带版本的 packedIn 定位：容器描述符及相对有效载荷的偏移。packedIn schema 为 agentcv-packed-asset-1。
逻辑 $asset 是原始内容身份，未必存在同名独立文件；不能只替换写入器。
所有权键必须绑定完整定位，物理容器也须获得同一工程授权；不能沿用只比较四个逻辑字段的旧键。

当前已实现：描述符键绑定 schema、物理容器四字段及 offset，且不依赖 JSON 对象字段顺序。清单和日志索引同时保留逻辑/物理资产。保存时从日志及清单查询已有定位，逐字节验证后复用；同次保存的同一容器只读取、解析和校验一次，VerifiedPack 不跨保存存活。

| 路径 | 必须完成的改变与证据 |
| --- | --- |
| inspection_files 保存 | 保留原字节，仅打包新逻辑资产；资产成功后再保存记录、提交日志；失败不得返回 SAVED |
| workspace 读取 | 兼容旧描述符；核对所有权与实际容器，再验证索引、边界、逻辑内容及哈希 |
| journal/manifest | 新所有权键绑定版本/容器/偏移；同时登记物理容器；拒绝伪造定位及跨资产授权 |
| Save As / relocation | 复制完整物理闭包并核对，保持记录与产物原字节；删除来源后仍能独立回读 |
| history_transfer | 导出实际物理容器，删除来源、导入后逐份还原原始资产 |
| Git/LFS | 验证并保存物理容器及普通记录；新旧混合版本回滚后仍有完整闭包 |
| 桌面独立判据 | 继续比较完整事实和全部产物字节；只扩展容器寻址，不减少字段、样本或计时范围 |

跨容器、跨工件去重继续生效：在受锁保护的索引中找已有逻辑资产，验证确切内容后复用原定位；只打包新内容。
不能每张新图都保存一份相同代码来换取速度。同一逻辑内容的多个合法历史定位须保留；发现已有损坏必须报错，不能重新写包掩盖问题。
预算超限应在准备阶段明确选择已支持的路径；损坏后不可悄悄回退。

确认顺序须包含资产、记录与日志的实际提交。现有同步/重命名仅作局部对照基线；中断、截断日志、重启恢复及已确认记录可读性还需故障注入证明。

当前记录仍在所有资产成功后保存、再同步资产日志，最后才返回 SAVED。已确认的定位在下一次保存前从实际磁盘重新验证。局部失败可留下未提交孤立文件，损坏不能通过另写一个包隐藏。尚未宣称完整断电恢复能力。
